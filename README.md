# ceramicsdoronina checkout functions

Netlify Functions that create Stripe Checkout sessions for the ceramicsdoronina.it shop.

## Repos and hosts
- Site (static): GitHub Pages repo `ceramicsdoronina`, served at https://ceramicsdoronina.it
- This repo (`ceramicsdoronina.netifly`, folder name has a historical typo): deployed on Netlify; only `functions/` is served. `publish` is the placeholder folder `public/` so source files are not published.
- Endpoints: `/.netlify/functions/create-checkout`, `/.netlify/functions/stripe-webhook`, `/.netlify/functions/catalogue` (public read-only catalogue, GET, version 2)

## Environment variables (names only; set in Netlify; this README is the canonical list)
- `STRIPE_SECRET_KEY`: Stripe secret key (test `sk_test_...` or live `sk_live_...`)
- `STRIPE_WEBHOOK_SECRET`: signing secret of the webhook endpoint
- `ALLOWED_ORIGINS`: comma/space separated, no trailing slash, include www if used. Empty or unset means the function refuses everything (fail closed, logged as `config_missing`)
- `SITE_URL`: default `https://ceramicsdoronina.it`; the only source of success/cancel URLs and image URLs. Must be a valid `https://` URL without query/hash (`http://localhost` is accepted for local development only); otherwise the function logs `config_invalid` and answers a generic 500
- `OWNER_NOTIFY_WEBHOOK_URL`: optional but see "Owner notification" below. Must be `https://`; the order summary is POSTed there as JSON `{text, summary}` (5 s timeout, redirects refused)
- `CATALOGUE_VASI_CSV_URL`, `CATALOGUE_MASTERCLASS_CSV_URL`, `CATALOGUE_CERTIFICATI_CSV_URL`: optional. The "Publish to web" CSV links of the three tabs `Vasi`, `Masterclass`, `Certificati` of the owner's single Google Sheet. Each must be `https://` on `docs.google.com` only; anything else is rejected (warn `catalogue_source_rejected`, that tab falls back to the snapshot). If any of the three is set the tab mode is used, and a tab whose variable is unset behaves like a failed tab (warn `catalogue_source_not_configured` once, snapshot items for that tab). None set: see the deprecated variable below. Only the host is ever logged, never the full URL
- `CATALOGUE_CSV_URL`: DEPRECATED (single 9-column `Catalogue` sheet, shipped before the three-tab sheet). Read only when none of the three variables above is set; then the old single-CSV mode keeps working (`tabs` null in the endpoint). With none of the four set, the bundled snapshot is used and one warn `catalogue_source_not_configured` is logged. Same host rules
- `CATALOGUE_WRITE_URL`: optional. The Apps Script web app `/exec` URL used to mark a paid one-off piece as sold. `https://` on `script.google.com` only
- `CATALOGUE_WRITE_SECRET`: shared secret sent to that script (must equal the script property `SECRET`). Never logged
- How they fit together: `ALLOWED_ORIGINS` and `SITE_URL` only concern `create-checkout` (browser origin, redirect and image URLs); the `catalogue` endpoint is public and answers CORS `*`. The `CATALOGUE_*` variables are read by all three functions through `functions/_catalogue-source.js`. Without them everything keeps working from the snapshot, but a sold piece must then be marked by hand

## Contract: POST create-checkout
Request JSON: `{"items":[{"id":"v1","quantity":1}], "locale":"it"|"en"|"ru"}`. Any other field (price, name, currency, image, return_base, origin, ...) is ignored; an unknown locale is treated as missing (Stripe auto-detects, Italian copy). Ids are catalogue ids (vases `v1..`, masterclass `mc1..`, gift cards `gc-50`, `gc-150`, `gc-200`, `gc-300`). Limits: 1..30 items (the catalogue has 23 products), quantity 1..`maxQty` (vases 1; gift cards 10); repeated ids are merged. For a MASTERCLASS item `quantity` means PERSONS (1..20 for a price table, up to 999 for linear pricing, see below) and the line is priced by group size, see "Masterclass: group prices and seats"; the same masterclass id twice in one request is rejected.

Responses (all carry header `x-request-id`; CORS headers only when the origin is allowed):
- 200 `{"url","session_id","request_id"}`
- 400 `{"error":<code>,"request_id","item_id"?}`: bad JSON/shape, unknown id, sold item, bad quantity; also missing Origin. `item_id` (the catalogue id string) is present for `unknown_item`, `item_sold`, `quantity_too_high`, `invalid_quantity` and, for masterclass lines, `sold_out` (no seat left, holds included), `not_enough_seats` (more persons than seats left), `group_size_unavailable` (no price for that group size, or more persons than the ceiling: 20 for a price table, `maxQty` ceiling for linear pricing) and `duplicate_item` (same masterclass twice); it is absent for body-level errors. The site removes that line from the cart and tells the customer
- 403 origin not allowed; 405 wrong method; 502 Stripe error; 500 generic/misconfiguration

Checkout sessions expire after 31 minutes (`expires_at`; Stripe's minimum is 30). Stripe line item metadata key is `item_id`; session metadata `bookings` (only when the cart has a masterclass) is `mc1:2,mc3:1` (masterclass id : persons; same 500 character rule, warning `metadata_bookings_truncated`); session metadata `item_ids` is a comma list of whole ids (ids that would exceed Stripe's 500 character limit are dropped from the end and a `metadata_item_ids_truncated` warning is logged).

Shipping: 40 EUR if physical subtotal < 200 EUR, 20 EUR if < 500 EUR, else free; digital items never count; digital-only carts get no address or shipping. The shipping rate label is localised (it "Spedizione", en "Shipping", ru "Доставка"). Shipping is a Stripe shipping option, so promo codes do not discount it. The allowed country list (`ALLOWED_COUNTRIES`, EU + Norway + Switzerland) is pending owner confirmation; the delivery copy on the site (`messages.js`) and `ALLOWED_COUNTRIES` must always change together.

Code layout: `functions/_catalogue-source.js` (three-tab sheet reader, cache, per-tab fallbacks, sold write-back), `functions/catalogue.js` (public endpoint, version 2), `functions/create-checkout.js` (`validateBody`, pure `buildSessionParams({items, locale, catalogue, siteUrl, now})`, handler), `functions/_shared.js` (Stripe client factory and pinned API version, body decoding, log redaction; the underscore keeps Netlify from deploying it as a function).

## Catalogue and sold items: the Google Sheet is LIVE
One Google Sheet document with THREE tabs is the single source of truth for BOTH the commerce data (what `create-checkout` charges) and the display data (what the site shows). Each tab is published as CSV with its own link (`CATALOGUE_VASI_CSV_URL`, `CATALOGUE_MASTERCLASS_CSV_URL`, `CATALOGUE_CERTIFICATI_CSV_URL`) and read server-side. The tabs have the same headers as the old ODS files (copies in `test/fixtures/catalogue-tab-*.csv`):
- `Vasi`: `id,name_ru,name_it,name_en,short_*,long_*,height,diameter,material*,technique*,finish*,img1..img6,venduto,price_old,price_new,shopify_variant_id`
- `Masterclass`: `id,name_it,name_en,name_ru,short_*,long_*,date,time,level,seats_total,seats_booked,price_1..price_20,img1` (new schema, see "Masterclass: group prices and seats"; the legacy schema has `spots,price` instead of the seat and price columns)
- `Certificati`: `id,name_it,name_en,name_ru,short_*,long_*,img1,amount_eur`

Commerce derivation (same as `tools/build-catalogue.py`, which stays the generator of the snapshot):
| Tab | type | price | maxQty | sold | image |
|---|---|---|---|---|---|
| Vasi | physical | `price_new` | 1 | `venduto` in `si, sì, yes, true, 1, x` (any case; `no`, empty, `-` = not sold) | `images/catalogue/<img1>` |
| Masterclass | digital | seat schema: `price_1` (cheapest defined tier if blank); legacy: `price` (`100€`) | seat schema: linear `min(ceiling, seatsFree)`, table `min(20, seatsFree, highest offered group size)` (`seatsFree` ignored when unlimited); legacy: first number in `spots` (`Max 6 persone` -> 6; none -> 6) | seat schema: limited and no seat left (never when `seats_total` is blank = unlimited); legacy: never | `images/masterclass/<img1>` |
| Certificati | digital | `amount_eur` | 10 | never | `images/certificati/<img1>` |
Names come from `name_it/en/ru` (a missing language falls back to the first filled one, order it, en, ru; for the Masterclass tab each title is optional but at least one is required). Empty or `-` in `img1` means no image.
- Validation: `id` `^[a-z][a-z0-9-]{0,31}$`, unique ACROSS the three tabs (a later tab's duplicate row is rejected with warn `catalogue_duplicate_id`; a repeated id inside one tab drops only the LATER row, the first one keeps selling: every workshop session needs its OWN id, e.g. `mc7`, never a copied `mc6`); price whole or decimal euros in (0, 10000], `120`, `120,50`, `120.50`, optional `€` (same strict rules as `test/fixtures/price-cases.json`: at most 2 decimals, no thousands separators); image = a plain file name (no `/`, `..`, scheme or query) ending in `jpg jpeg png webp svg`.
- Failure policy per tab: an invalid row, or a row repeating an earlier id, is dropped (warn `catalogue_rows_dropped`, ids only). A missing required column, zero valid rows, more than half of the rows invalid, or a failed fetch makes THAT tab use its own last good copy (up to 24 h, `source: "stale"`), else the snapshot items of that type (`source: "snapshot"`). The other tabs are not affected.
- Cache: 60 s in memory per function instance and per tab, 5 s fetch timeout, 256 KB per CSV, 15 s back-off after a failure.
- `GET /.netlify/functions/catalogue` answers `Cache-Control: public, max-age=60` and `{version:2, source, sources:{vasi,masterclass,certificati}, items:[...], tabs:{vasi,masterclass,certificati}}`. `source` is the worst of the tabs (`sheet` < `stale` < `snapshot`). `items` is the version 1 list (`id,type,name_it,name_en,name_ru,priceCents,image,maxQty,sold`); masterclass items also carry `tiersCents`, `seatsTotal`, `seatsBooked`, `seatsFree` (`seatsTotal` and `seatsFree` are `null` = unlimited; see "Masterclass: group prices and seats"). `tabs.<tab>` is `{headers, rows}` with one object per valid row, keyed by the whitelisted headers above and holding the values as in the sheet; `shopify_variant_id` and any unknown column (the owner can keep private notes in extra columns) are never exposed. In `tabs.vasi` the `venduto` value is the effective sold state (sheet OR `sold.json` OR marked locally gives `si`; otherwise the sheet value, or `no` when empty). In `tabs.masterclass` (seat schema) `seats_booked` is the EFFECTIVE value (sheet plus paid bookings the published CSV does not show yet) and each row has one extra COMPUTED string field `seats_free` (`""` when the seats are unlimited; the only field not taken from the sheet; it is not listed in `headers`). `tabs.<tab>` is `null` when that tab is served from the snapshot: the site then falls back to its own ODS files.
- `functions/catalogue.json` is the last-resort OFFLINE SNAPSHOT (generated by `tools/build-catalogue.py` from the ODS files, never edit by hand); `functions/sold.json` stays a manual emergency override (array of ids) merged on top of whatever source is used.
- Deprecated fallback: with only `CATALOGUE_CSV_URL` set, the old single 9-column CSV (`id,type,name_it,name_en,name_ru,price,image,maxQty,sold`) is read as before (whole sheet rejected on a duplicate id, a missing column, zero valid rows or more than half invalid rows). Remove it from Netlify once the three tab variables are set.

### Owner runbook: change a price, mark sold, add a product
- Change a price, rename, change the texts, mark a vase sold or add a product: edit the right tab (`Vasi`, `Masterclass`, `Certificati`). Columns that matter: `id` (never reuse one), the three `name_*`, `img1`, and per tab `price_new` + `venduto` (Vasi), `seats_total` (blank = unlimited) + `price_1..price_20` (Masterclass; `seats_booked` is written by the script, see below), `amount_eur` (Certificati). Columns you add yourself (notes) are ignored and never published. Google's published CSV lags a few minutes, so the change reaches the shop (and checkout) after that delay.
- Add a vase: add a row in `Vasi` (new unique `id`, names, price, `venduto` empty or `no`, `img1` = file name) AND put the photo file in the site repo folder `images/catalogue/`, then `git push` the site repo. Masterclass photos go in `images/masterclass/`, gift card images in `images/certificati/`. Until the photo is pushed the row works but shows no picture.
- A vase paid through Stripe gets `si` in its `venduto` cell automatically (the webhook calls the Apps Script) and is treated as sold at once by the functions for 15 minutes, until the published CSV catches up.
- Optional, after bigger changes: refresh the offline snapshot with `python3 -B -I tools/build-catalogue.py` (it reads the ODS files, so keep them in step) and push.

### Google setup (once)
1. In the sheet: File > Share > Publish to web > choose the tab `Vasi`, format CSV > Publish; copy the link into `CATALOGUE_VASI_CSV_URL` (Netlify). Repeat for `Masterclass` (`CATALOGUE_MASTERCLASS_CSV_URL`) and `Certificati` (`CATALOGUE_CERTIFICATI_CSV_URL`). Then remove `CATALOGUE_CSV_URL`.
2. Extensions > Apps Script: paste `tools/apps-script/Code.gs` (reference copy of the script), save. Its constants at the top name the sheet (`Vasi`), the id column (`id`), the column written (`venduto`) and the value (`si`), the tab and columns used for seats (`Masterclass`, `seats_booked`, `seats_total`) and the idempotency tab `Ordini`.
3. Project Settings > Script properties: add `SECRET` = a long random value; put the same value in `CATALOGUE_WRITE_SECRET` (Netlify).
4. Deploy > New deployment > Web app > Execute as: Me, Who has access: Anyone. Copy the `/exec` URL into `CATALOGUE_WRITE_URL` (Netlify).
5. Updating an already deployed script (for example from the old `Catalogue` version): paste the new `Code.gs`, save, then Deploy > Manage deployments > pencil (edit) > Version: New version > Deploy. The `/exec` URL stays the same, so nothing changes in Netlify. The seat booking needs the v2 script (the calendar the v3 one, see "Masterclass calendar events"): until it is pasted AND deployed as a New version, a paid masterclass is reported as `script_outdated` and the owner notification asks to add the seats by hand (an old script ignores `bookings`), and a sold vase also asks to be marked by hand.
6. The tab must be named `Vasi` and have the columns `id` and `venduto`. Contract v3: `POST {"secret","session_id","ids":[...],"bookings":[{"id":"mc1","seats":2}],"customer":{"email","name","locale"}}` (with ids only the payload is `{"secret","ids"}`; `customer` is sent with bookings only) answers `{"ok":true,"version":3,"sheet":"Vasi","marked":[...],"booked":[{"id","seats","booked_after","total","overbooked","duplicate","calendar":{"status","reason?"}}]}` or `{"ok":false,"error":"forbidden|bad_json|bad_ids|bad_bookings|bad_sheet|bad_columns|bad_orders"}`; the function follows Apps Script's 302 and only trusts a final JSON body with `ok: true` AND `sheet: "Vasi"` AND, when bookings were sent, `version` 2 or later (5 s timeout, up to 2 retries with short backoff on network errors, 5xx or non-JSON answers; the webhook stops waiting after 4 s). An `ok: true` reply without `sheet: "Vasi"` (or without version 2 or later when bookings were sent) comes from the old script and is a failure with reason `script_outdated`.

### Failure matrix
| What fails | Effect |
|---|---|
| A tab unreachable, slow (5 s), over 256 KB, or rejected as invalid | that tab's own last good copy is served for up to 24 h (`sources.<tab>: "stale"`), then the snapshot items of its type (`"snapshot"`, `tabs.<tab>` null); warn `catalogue_fetch_failed` with `tab`, host and reason; retried at most every 15 s; the other tabs stay live |
| A tab variable unset, not https, or not `docs.google.com` | that tab uses the snapshot; warn once per cause |
| None of the four catalogue variables set | snapshot for everything; warn once `catalogue_source_not_configured` |
| Marking/booking write fails (or `CATALOGUE_WRITE_URL`/`SECRET` unset) | the piece is still treated as sold, and the booked seats as taken, locally for 15 minutes; warn `sold_mark_failed` / `sold_mark_not_configured`; the owner notification gets the line `ACTION: mark <ids> as sold in the sheet manually` (for masterclass bookings `ACTION: add <seats> seats to <id> in the sheet manually (seats_booked)`; with reason `script_outdated`, i.e. the deployed Apps Script was not updated, the line ends with `(Apps Script needs updating)`); the webhook still answers 200 to Stripe |
| Sheet is edited by hand and a locally marked piece is un-sold | stays sold for up to 15 minutes (local marker), then follows the sheet |

Only one-off pieces are marked: items with `type` physical and `maxQty` 1 in a PAID order (paid session, `no_payment_required`, or `async_payment_succeeded`); gift cards never. Ids come from the session metadata `item_ids`. Masterclass seats come from the session metadata `bookings`. Stripe retries re-mark harmlessly and never book a session twice (the script skips a `session_id` + item it already recorded in `Ordini`).

### Masterclass calendar events
After a PAID masterclass booking the Apps Script (it runs as the owner) creates a Google Calendar event in the owner's calendar and invites the customer and the owner's colleague. Needs the v3 `Code.gs`.
- What is created: ONE event per booking (Stripe session + masterclass id). Two bookings of the same workshop give two separate events at the same time; the script never adds guests to, or changes, an existing event, so independent groups never see each other, and guests cannot see, invite or modify (`setGuestsCanSeeGuests/InviteOthers/Modify` all false). Title `<workshop name in the customer's language> (2 persone | 2 people | 2 человека)`; description: workshop id, persons, customer name and email, booking reference (last 8 characters of the Stripe session id), nothing else. Start and end come from the `date` and `time` cells of the tab `Masterclass`, in Europe/Rome time: date `dd.mm.yyyy`, `dd/mm/yyyy`, `dd-mm-yyyy` (day first) or `yyyy-mm-dd`; time `10:00-13:30` (hyphen or en dash, spaces allowed) or a single `10:00` (lasts 2 hours).
- Who is invited: the customer (email from Stripe Checkout) and every address in the script property `OWNER_GUEST_EMAIL` (comma separated list, for example the colleague). The address is not in this repo: if the property is missing or empty the event is still created for the customer only and the reply says `owner_guest_missing`.
- Script properties (Project Settings > Script properties): `OWNER_GUEST_EMAIL` (set it, see above) and optional `CALENDAR_ID` (another calendar; default is the owner's main calendar).
- Check which code is deployed: open the `/exec` URL in a browser. The deployed script answers `{"ok":true,"script":"ceramicsdoronina-catalogue","version":8}`, where `version` is the `VERSION` constant at the top of `Code.gs` (the owner's deployment counter, bump it with every New version; the Netlify function only requires 2 or later) (a public health check, no secret and no data); an older script shows "Script function not found: doGet". The webhook's 200 answer also names it as `script_version`.
- Setup, once: paste the new `Code.gs`, save, select the function `authorize` and press Run: Google asks for the Calendar permission, accept it (it returns the calendar name). Then Deploy > Manage deployments > pencil (edit) > Version: New version > Deploy (the `/exec` URL stays the same). Without the permission the booking still works and the event is reported as `failed`.
- Retries: the tab `Ordini` has a 5th column `event_id` (an existing 4-column tab gets the header added automatically). A Stripe retry of a booking whose `event_id` is empty tries to create the event again; with an `event_id` it does nothing (`exists`), so an event is never created twice.
- Skips and failures never undo the booking (seats are still booked). The event is skipped (`skipped`) when the date or time cannot be parsed (`bad_date`) or the start is already in the past (`date_in_past`); a Google error is `failed` (`calendar_error`). In those cases, and with a v2 script that was not updated, the owner notification gets `ACTION: create the calendar event for <id> manually (<reason>)`, the log has `calendar_failed` / `calendar_skipped` (ids and reason only) and the 200 answer to Stripe has `calendar: "partial"` (`ok` when all events exist, `none` when there is nothing to book or no customer email).
- Test with a FUTURE date in the tab `Masterclass`: a past date is skipped by design.
- Privacy: the customer's email and name are passed from Stripe through the Netlify function to the Apps Script and into the Google Calendar invitation (Google sends the invitation email). Mention it in the privacy policy. They are not written to the sheet (`Ordini` keeps only ids) and not logged.

### Masterclass: group prices and seats
The tab `Masterclass` (templates with the current rows: `catalogue-tab-Masterclass-v3.csv`, the one to start from, and the older `-v2.csv`, both in `test/fixtures/`) has the columns `id,name_it,name_en,name_ru,short_*,long_*,date,time,level,seats_total,seats_booked,price_1..price_20,img1`.
| Column | Rule |
|---|---|
| `id`, `img1` | required, as in the other tabs |
| `name_it`, `name_en`, `name_ru` | each optional, at least one required; a missing one is filled with the first non-empty by order it, en, ru (used for the Stripe product name). `short_*`, `long_*` also optional |
| `date`, `time`, `level` | free text for the site (`12.01.2026`); the functions never parse the date |
| `seats_total` | integer 1..9999 (may exceed 20: a limited linear workshop with 30 seats takes up to 30 persons); blank (or no such column) = UNLIMITED seats: nothing is ever sold out, no seat check and no holds lookup. A non-integer or out-of-range value drops the row (warn `catalogue_rows_dropped`) |
| `seats_booked` | integer >= 0, blank = 0 (also counted for unlimited workshops, so you see the total); written by the Apps Script after each paid booking, you may also edit it by hand (for example for a booking taken in person) |
| `price_1`..`price_20` | TOTAL price in euros of a booking of N persons (same strict price rules as everywhere: `100`, `180,50`, optional `€`). `price_1` must exist as a column (`price_9`..`price_20` may be missing: treated as blank). A filled but invalid cell drops the row (a typo never silently closes a group size) |
- Pricing rule A = LINEAR pricing (default, same price per person): if `price_2`..`price_20` are ALL blank (or absent), the customer can book ANY number of persons N at N x `price_1`, not only up to 20. Technical ceiling `maxPersons = min(999, floor(99999999 / price_1 in cents))` (99,999,999 cents is Stripe's maximum amount; e.g. `price_1` = 5000 EUR gives 199, 100 EUR gives 999). With `seats_total` blank the ceiling is the only limit; with `seats_total` filled the limit is `min(ceiling, seatsFree)`. Example: only `price_1` = `100` gives 1 person 100, 7 persons 700, 150 persons 15000. The site shows a free numeric field (no dropdown) for linear items. As soon as ANY of `price_2`..`price_20` is filled the pricing is a TABLE: rule A is off and ONLY the sizes with a filled price are bookable (blank = not bookable, maximum size 20, as before). Example: `price_1`=`100`, `price_2`=`180`, `price_4`=`320` offers 1, 2 and 4 persons only; filling `price_1`..`price_8` (and nothing above) offers 1..8 and not 9.
- Rules: a booking is for N persons (linear: 1..`maxQty`; table: 1..20); with explicit tiers the price is the table value for THAT group size, not linear (`price_2` need not be twice `price_1`); two separate bookings of 1 person each pay `price_1` + `price_1`, because each checkout prices its own group size. Limited seats: `seatsFree = max(0, seats_total - seats_booked)`, e.g. 30 seats with 5 booked leaves 25 free (linear: `maxQty` 25; table: capped at 20), 8 booked of 8 leaves 0. Unlimited (`seats_total` blank): `seatsTotal` and `seatsFree` are `null`, never sold out, never overbooked.
- Item fields in `GET catalogue`: `priceCents` (tier of 1 person, the cheapest defined tier if `price_1` is blank), `tiersCents` (20 entries, `null` = not bookable; for linear items the first 20 sizes, kept for compatibility), `pricing` (`"linear"` or `"table"`; legacy rows and snapshot items are `"table"`), `linearCents` (only when linear: `price_1` in cents, the price of one person), `seatsTotal` (number or `null`), `seatsBooked`, `seatsFree` (number or `null`), `maxQty` = linear: `min(maxPersons, seatsFree when limited)`, table: `min(20, seatsFree when limited, highest offered group size)`, `sold` = limited and no seat left.
- Checkout: `quantity` = persons (integer; linear 1..`maxQty` ceiling, table the sizes with a price). One Stripe line per masterclass: `unit_amount` = the tier, or N x `linearCents` for linear items (always within Stripe's maximum, else `group_size_unavailable`), quantity 1, product name `<title> (2 persone | 2 people | 2 человека)` (Italian `1 persona`, English `1 person`, Russian general plural rule on n%10 and n%100: 1 человек, 2-4 человека, 5-20 человек, 21 человек, 22 человека, 111 человек, for any N up to 999), line metadata `{item_id, seats}`. Unlimited workshops skip the seat check and the holds lookup entirely. For limited ones seats still bookable = `seatsFree` minus the HOLDS: before accepting a masterclass line the function lists the OPEN Checkout Sessions (`status: open`, up to 100) and subtracts the seats in their `metadata.bookings`, so two customers cannot both get the last seats while one is paying. A session holds its seats until it is paid or expires (30 minutes at most, `expires_at`). If Stripe cannot be asked the check fails open (warn `holds_unavailable`) and only `seatsFree` decides; the list is not called for carts without a masterclass.
- After the payment the webhook sends the bookings to the script (one call together with the vase marking); the script adds the seats to `seats_booked` and records `session_id, item_id, seats, at, event_id` in the tab `Ordini` (created when missing, no customer data). The same session is never booked twice, so Stripe retries are safe. If the new total exceeds `seats_total` (a number; blank = unlimited, never overbooked) the script still records it and the owner notification gets `OVERBOOKED <id>: refund this booking or move it`. The notification always lists the persons per masterclass (`Masterclass persons: mc1 x 2`).
- Residual race window: the published CSV lags a few minutes. The function covers that gap by counting the paid bookings locally for 15 minutes (effective `seatsBooked` in items and rows) and by the holds of open sessions, but these live in one function instance's memory: a cold or second instance, or a hold list beyond 100 open sessions, can still sell a seat twice within a few minutes. That is caught by `OVERBOOKED`. Once the CSV has caught up the local count is still added for the rest of the 15 minutes, so for a short time the workshop can look fuller than it is (the safe direction).
- LEGACY sheet (columns `spots` and `price`, no `price_1`): the item behaves as before (`maxQty` from `spots`, price linear N x `price`, never sold, no seat tracking: `seatsBooked` 0). `tiersCents` is derived linearly (up to `maxQty`, at most 20, `pricing` `"table"`, so legacy rows stay capped; blank `spots` keeps its default of 6, it does NOT become unlimited) so the item shape is the same. The bundled snapshot masterclass items are shaped the same way. When `price_1` exists only the new columns are used.
- Migration from a sheet with `price_1`..`price_8` and the old default of 8 seats: add the columns `price_9`..`price_20` if you want bigger groups (optional, the functions tolerate their absence). ## Tests
`npm test` (runs `node --test`; Stripe is faked, no dependencies needed). The Apps Script reference copy is run in a vm against an in-memory sheet (`test/apps-script.test.js`). The fake client (it also fakes `checkout.sessions.list` for the seat holds) enforces Stripe API rules (expires_at window, custom field label length, metadata limits, unit amounts, https URLs, shipping only for physical carts). CI: `.github/workflows/test.yml`. `test/fixtures/price-cases.json` holds the price-string cases shared with the site's JS money parser; `test/fixtures/catalogue-sheet.csv` is a copy of the deprecated single-sheet CSV and `test/fixtures/catalogue-tab-*.csv` are copies of the three published tabs (their derived items must equal `functions/catalogue.json`). ## Stripe webhook setup
Stripe Dashboard > Developers > Webhooks > add endpoint `https://<netlify-site>/.netlify/functions/stripe-webhook` and subscribe to exactly these events:
- `checkout.session.completed` (paid: "New paid order"; not yet paid, e.g. delayed payment methods: "AWAITING PAYMENT, do not ship")
- `checkout.session.async_payment_succeeded` (notified as paid)
- `checkout.session.async_payment_failed` (notified as failed, do not ship)

Copy the signing secret into `STRIPE_WEBHOOK_SECRET`. The signature is verified on the raw body. Deliveries are stateless and may repeat; the notification is informational, so duplicates are harmless (`event_id` is logged). If the owner notification cannot be sent (non-2xx or network error) the function answers 500 so Stripe retries. Customer text in the summary is length-capped and neutralised for chat markup; every log line carries `request_id`; no customer PII is logged.

## Owner notification (mandatory decision)
Without `OWNER_NOTIFY_WEBHOOK_URL` (or the Stripe Dashboard owner emails) there is NO owner notification: the only trace of an order is a `console.warn` event `owner_notify_not_configured` in the Netlify function log (session id, event id, catalogue ids, total, currency, payment status, country; no personal data) and the order in the Stripe Dashboard. Either set `OWNER_NOTIFY_WEBHOOK_URL` (Slack/Teams/Make/Zapier style endpoint that accepts `{text, summary}`) or enable Stripe Dashboard > Settings > Emails owner notifications for successful payments. The channel is the owner's choice.
